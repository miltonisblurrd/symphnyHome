## Test the skill (three ways)

### 1. Cursor IDE (manual, no API key)

Agent mode prompt:

```
Use the symphony-content-engine skill. Generate the full pack for the next pending topic. Reference-first: blog, guide, faq, then WWDC youtube-script with Sources. Write to content/packs/. Update calendar status.
```

Or invoke the skill by name: `@symphony-content-engine` with the same instruction.

**Pass:** new folder under `content/packs/`, script has `## Sources`, calendar `status: generated`.

### 2. SDK dry-run (no API call)

Preview the next topic and full prompt:

```bash
npm run content:dry-run
npm run content:dry-run -- --topic automation-vs-orchestration
```

### 3. SDK local run (realistic — streams into your repo)

1. Put **`CURSOR_API_KEY`** in **`.env`** or **`.env.local`** (gitignored) — see `.env.example` for variable names only (never put real keys in `.env.example`).
2. Or `export CURSOR_API_KEY='cursor_...'` in your shell.
3. Run:

```bash
npm run content:next
```

This uses **`Agent.create` + streaming** on your machine (`cwd` = repo root). You should see files appear under `content/packs/YYYY-MM-DD-<id>/` and `calendar.json` updated.

**Options:**

```bash
npm run content:next -- --topic fail-gracefully
npm run content:next -- --force          # regenerate existing topic
npm run content:next -- --no-stream    # one-shot Agent.prompt
npm run content:cloud                  # cloud VM + auto PR
```

### 4. GitHub Actions (cloud + PR)

1. Add repo secret **`CURSOR_API_KEY`**.
2. Actions → **Content Engine** → Run workflow.
3. Choose `cloud` or `dry-run`, optional `topic_id`.

## Publish to symphonystudio.io `/news`

| URL | Source |
|-----|--------|
| `/news` | Index of published packs (with article thumbnails) |
| `/news/[slug]` | `blog.md` + **pack hero image** as full-page hero |
| `/news/[slug]/guide` | `guide.md` + **same image** as thumbnail |
| `/news/[slug]/faq` | `faq.md` |

### Article image (one per pack)

The skill writes `image-prompts.md` with **one** 16:9 prompt. That image is reused for:

- Blog article hero on `/news/[slug]`
- Guide thumbnail on `/news/[slug]/guide`
- Open Graph / Twitter cards

**Generate:** ask Cursor to create the image from `image-prompts.md` (see `visual-style.md`). Saves to:

- `content/packs/.../assets/article-hero.jpg`
- `public/news/<slug>/hero.jpg`
- `metadata.json` → `"heroImage": "/news/<slug>/hero.jpg"`

```bash
npm run content:sync-heroes   # copy pack assets → public/news/
npm run content:publish-check
```

**Your steps:**

1. Review pack copy (tone still education-first).
2. Run `npm run content:publish-check`.
3. In `content/packs/.../metadata.json` set `"published": true` and `"publishedAt": "ISO-date"`.
4. Set calendar `"status": "published"` for that topic.
5. Deploy site — pack appears on `/news` and in `sitemap.xml` + `public/llms.txt`.

**Currently live:** `missing-layer` only (`published: true`). Other four cornerstones are optimized but `published: false` until you approve.

## Troubleshooting SDK

| Issue | Fix |
|-------|-----|
| `Missing CURSOR_API_KEY` | Set in `.env` / `.env.local` or export in shell (runner loads both automatically) |
| `No pending topics` | All generated — pick lower priority or add calendar entries |
| Agent didn't update calendar | Manually set `"status": "generated"` for that `id` |
| Cloud PR empty | Ensure API key has repo access to `symphnyHome` |
